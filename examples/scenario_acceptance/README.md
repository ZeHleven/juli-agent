# M08：三个场景使用同一套扩展接口

这个示例验证“上传本次文件，结合已保存背景，经过问答整理依据”的工程流程。模型行为是预设脚本，不进行真实判断；表中的招投标、求职和设备信息全部为新造的合成资料。

| 场景 | 本次文件 | 已保存背景 | 场景结果字段 |
|---|---|---|---|
| 招投标研判 | 项目要求 | 组织经历、交付记录 | `summary`、`missing_information` |
| 岗位匹配 | 岗位 JD | 个人经历、作品 | `summary`、`questions` |
| 设备选择 | 候选设备 | 个人约束、使用环境 | `summary`、`checks` |

每种场景都跑完整资料和缺少背景两条路径，共六组结果。完整路径回读三份资料；缺少背景时只绑定本次文件，即使其他资料已保存在工作空间中，也不会自动进入该任务。

## 运行

在仓库根目录，使用独立虚拟环境并安装开发依赖：

```bash
python -m pip install -e ".[api,documents,model,dev]"
python -m examples.scenario_acceptance
python -m pytest tests/test_scenario_acceptance.py
```

输出明确包含 `real_model_calls: 0`、`analysis_quality_evaluated: false`、每组动作数、引用资料数和预设的场景结构结果。脚本不读取旧系统数据库或模型密钥，使用临时合成库并在退出时清理；不启动网页服务器。API 由 `TestClient` 在进程内调用，不能把这个输出称作浏览器实测或真实模型评测。

完整资料路径各为 10 个动作、6 次脚本模型调用；缺少背景路径各为 6 个动作、4 次脚本调用。它们经历上传、角色绑定、追问、重建应用、提交回答、检索、逐份回读、结果持久化和引用读取。[验收记录](../../docs/scenario-acceptance.md)说明验证范围和已知限制。

`examples/` 和 `scenarios/` 是仓库文件，不会随 wheel 自动安装。仅安装 Python 包的开发者需要另外保留这些示例文件，或提供自己的场景目录。普通运行不需要 LangGraph。

## 文件分工

- [cases.json](cases.json)：场景路径、资料角色、问题、合成回答和预设结果。场景差异保存在数据中。
- [data](data)：九份简短 Markdown 合成资料，不含个人或企业真实数据。
- [设备选择包](scenarios/equipment-choice/scenario.json)：新角色与嵌套结果 schema。它可按公共加载接口单独注册，不依赖场景名分支。
- [fixture_model.py](fixture_model.py)：从持久消息恢复进度的通用脚本模型；按检索候选逐份回读，复制合成原文作为事实块。它不是可用于分析真实资料的模型。
- [harness.py](harness.py)：受信管理员创建临时身份与显式迁移；用户流程均通过公共 HTTP API。背景先保存，任务只提交版本 ID。
- [专项测试](../../tests/test_scenario_acceptance.py)：正向流程、背景复用、版本固定、作用域、角色/结构拒绝和预算边界。

## 开发新场景

1. 复制 `scenarios/minimal`，修改 manifest 中的 ID、版本、资料角色，编写方法指导与结果 schema。
2. 使用 `python -m juli validate <包目录>` 校验。包属于部署者安装的受信配置，不能让普通上传文件替代它。
3. 放入已安装场景目录供 `load_registry` 加载，或通过 `ScenarioRegistry.register(load_scenario(path))` 注册。
4. 使用已有资料版本与角色建立任务；资料正文不会随每个提问重新上传，但每次任务仍需显式绑定授权资料。
5. 使用相同的运行器执行，检查输出结构、原文依据和资料不足处理。增加真实模型效果评测时，另行确定模型、外发范围和预算。

添加一次新的自定义场景不要求改写核心。M08 也额外测试了将设备选择包及三个角色重命名为其他 ID 后继续运行。没有把场景文件里的 Python 当作插件执行。

## 预算与其他限制

默认 32000 输入计量单位无法完成本例的三份资料流程，实测在第 4 次模型请求准入时停止。本示例由受信服务端显式配置 `TaskBudget(max_input_tokens=128000)`，默认值没有提高；预算仍在新任务创建时固定，HTTP 客户端不能设置额度。详见 [预算配置](../../docs/workbench.md#部署者配置新任务预算m08)。

新任务复用背景是复用已保存的资源版本，不是无限上下文记忆，也不是自动选取工作空间中的全部资料。更新背景会创建新版本，旧任务不改变；是否绑定新版本由调用方明确决定。

本例没有 OCR、语义匹配评分、资质规则引擎、任意代码插件或真实模型质量结论。结构结果为脚本预置值，引用回读通过不意味着推理结论已被证明。需要新增工具时，还须提供受控执行器并进行权限装配，不能只改工具名字。
