# 首轮人工验收标准

先固定题目、资料版本、场景指纹、模型与配置，再运行并评分。不得根据实际回答修改同一轮金标使其通过。发现题目含糊、评分错误或运行器故障时，保留原记录，标明原因与修订版本，不归入模型推理错误。

## 逐题核对

每个评分文件的 `required_findings` 是可接受回答必须覆盖的实质内容。它不是给模型复述的标准答案，也不要求完全相同的字句、检索词、工具顺序或引用数量。按每项填写：

| 分值 | 含义 |
|---|---|
| 2 | 关键含义正确、范围合适，所用证据支持结论；必要的限定被保留 |
| 1 | 方向基本正确，但解释、限定或证据覆盖不完整；不得掩盖实质性错误 |
| 0 | 错误、遗漏、无依据确定判断，或原文与结论矛盾 |
| 未评 | 尚未运行、输出缺失、资料/评分存在争议；写明原因，不当作零分或通过 |

`critical=true` 的项必须达到 2 分，才能称为“本题关键要求满足”。非关键项单独报告，不用总平均分抵消关键失败。`allowed_conclusions` 描述合理范围，不是必须选用的词句；只要满足事实、限制和决策条件，可以有不同建议。

涉及缺失或冲突的 `required_findings` 与初始 `allowed_conclusions` 按回答前阶段判断；`after_answer_expectation` 按回答后阶段判断，评分必须阅读完整交互。不能因为用户已经补充并消除了缺口，就要求最终回答仍保持“未知”。同样，初始阶段不允许利用回答卡提前替模型消除冲突。

## 七个评价维度

1. **关键条件覆盖。** 对照金标检查硬要求、偏好、否定、期限、数值与单位。覆盖率的分母是本题明确列出的关键义务，不能只统计模型主动提到的内容。
2. **双方资料对照。** 判断是否把要求与背景证据联系起来。分别总结两个文档不等于完成匹配分析；缺证明不等于确定不具备。
3. **事实与引用。** 检查整个答案，包括最终摘要、推断、建议与场景结果，不能只检查标为 fact 的段落。对每个可核对的实质断言记录支持、矛盾或证据不足。引用存在且可打开，只证明来源可查；人工仍需核对原文含义。由几条事实计算或推断出的结论，应给出依据与推导，不要求原文已经逐字写出计算结果。
4. **不确定性。** 关键缺失、同等级资料冲突、用户自述与文件核验需要分清。可给条件性建议，不得强行作精确评分、能力否定或结果保证。查不到候选不证明文件中没有该条件，必须检查是否漏解析或漏检索。
5. **追问闭环。** 是否只问影响结论且材料没有回答的事项；回答后是否采纳、更新判断并停止重复询问。操作者按回答卡提供用户陈述，不主动提示正确结论；回答卡内容不作为原文件证据伪造引用。
6. **配对稳定性与迁移。** 关键条件变动时，相关判断应变化；只改无关内容或顺序时，核心判断应保持。检查新场景仅依赖场景包与通用工具，并在调优前保留该场景的结果。
7. **完成与开销。** 记录真实运行状态、动作数、模型调用数、重复搜索、澄清轮数、总耗时和供应商报告用量。框架输入计量不是供应商账单；费用按当时实际模型价格另算。尚未确定模型和预算，不预设本轮成本或耗时成绩。

## 不能被平均分抵消的问题

- 编造影响判断的经历、资格、数值、条款或引用，或者原文明确相反却下肯定结论。
- 漏掉明确的硬性条件，导致对适配/资格/预算给出相反结论。
- 使用未绑定资料、其他主体资料或把文档文字当平台授权；本套基本文本题未完整覆盖该运行边界，发现则单独登记。
- 明知核心信息不足或冲突，仍声称全部满足；用“用户可能愿意改变”替代当前明确约束。

遇到这些情况标为关键失败，逐条保留原文和原因。最终评分由人工复核；自动结构检查或另一个模型给出的评分不能单独证明分析正确。

## 判定与归因

逐项标记“原文件是否有信息 → 解析文本是否保留 → 搜索候选是否出现 → 是否回读 → 模型是否正确解释”。失败类别可多选：资料设计/金标问题、解析、检索、模型推理、协议格式、预算停止、运行器/服务、操作者回答、未定位。

例如原文否定词被解析遗漏，应先登记解析问题；模型读到了完整否定句仍作相反判断，才有证据归因于解释错误。响应被严格 JSON 或工具格式校验拒绝时，同时记录原始可见响应与协议错误，不自动说成知识能力不足。

待澄清是中间状态。需回答的题在回答前不能算最终成功；资料充分题的完成状态也不等于答案正确。每次独立运行均保留，不挑最好一次；汇总报告逐次通过情况以及同题稳定性，同时保留未评和运行错误。

## 保存证据

未来运行放在 `.local/quality-eval/<suite-version>/<run-id>/<case-id>/trial-<n>/`。保存实际发送的合成问题与资料清单、场景/源码/配置指纹、API 返回的可见响应、工具输入输出、追问及回答、最终任务状态、时间和用量。密钥与 Authorization 头不进入日志。

评分表记录每个判断对应的响应片段和原文位置。实机图片、回放图与示意图要分别标注；本轮没有实机或真实响应，不能制作看起来像已测成功的效果图。
