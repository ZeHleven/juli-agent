# M08 场景扩展验收

日期：2026-09-22。运行包版本：`0.1.0.dev6`。

## 完成范围

招投标、岗位匹配和独立设备选择包，通过同一个持久运行器与 HTTP API 完成上传、资料绑定、追问、恢复、检索、原文回读和结果保存。每个场景覆盖完整资料及背景缺失。新增设备选择包使用三种角色和不同的嵌套结果结构，不修改核心或增加业务名称判断。

后台资料可保存一次，在后续新任务中继续使用其版本 ID。专项测试为三种场景各创建第二份新文件，复用已保存的背景；更新一份背景后，旧任务的快照、结果和旧版本引用仍保持不变。未绑定资料和其他工作空间资料即使包含相同关键词，也不会进入结果引用。

这些是合成数据和脚本模型的工程验收。完整流程有 3 份引用、10 个动作、6 次脚本调用；背景缺失流程有 1 份引用、6 个动作、4 次脚本调用。没有真实模型效果、召回质量、决策准确率或付费接口评测。

## 发现并处理的实际问题

原先只有默认任务预算可用。三份资料的合成流程在第 4 次模型调用准入时停止：默认输入上限为 32000，已有 3 次模型调用、5 个动作、约 22445 输入计量单位；下一次请求的上下文会使累计量超限。

新增受信配置入口 `create_app(..., task_budget=TaskBudget(...))`，通过持久化服务将预算固定进新任务快照。示例显式使用 128000 输入计量单位；它是验收配置，不是对真实模型的推荐额度。核心 `TaskBudget`、默认额度、运行器和数据库迁移保持不变。

客户端传入 `budget` / `task_budget` 会收到 422。服务端配置改变后，原任务继续使用原预算；同一幂等创建请求也返回原任务。只有新的创建请求采用新配置。这避免通过重启、重试或客户端字段悄悄改变执行额度。

本轮还修正了两处测试假设：Windows 异步事件循环需要本机 socket 对，外网阻断应保留这一系统行为；资源列表返回的是版本行，背景更新后应分别核对资源数和版本数。没有为适应测试而修改产品的资源列表语义。

## 验证与复现

新增 26 项测试，覆盖六组流程、背景跨任务复用与版本固定、未绑定/跨空间隔离、场景输出类型及额外字段拒绝、必需角色与未声明角色拒绝、默认预算停止、配置更新/幂等/客户端越权，以及重命名后的新场景和新角色运行。它们与原有回归统一执行：

```bash
python -m pytest
python -m examples.scenario_acceptance
```

测试中的外网连接被拦截，保留 Windows 事件循环所需的 loopback 通信；没有调用外部模型。测试重新构造应用以验证持久状态，不把它描述为本轮完成了全套进程崩溃或浏览器验收。进程崩溃语义沿用 M05/M07 的已验证实现。

安装包验证从源码目录外、隔离 Python 入口加载构建的 wheel，再运行这六组示例；确保预算配置入口与流程使用的是已安装包。JSON 输出以 UTF-8 编码，合成中文不因 Windows 控制台编码而损坏。汇总见 [M08 结果](../examples/scenario_acceptance/results.json)，脚本与输入见 [示例说明](../examples/scenario_acceptance/README.md)。

招投标和岗位匹配的说明更新后增加为 `0.1.1`，保留原有角色及结果 schema；新任务使用明确的版本，旧任务继续使用已保存的场景内容。自定义模板不变，新增设备选择包仅在示例中安装。
