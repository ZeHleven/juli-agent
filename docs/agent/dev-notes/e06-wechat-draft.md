# 格式通了，不等于任务完成

本地公众号草稿，未发布。本文记录据理 E06 的合成评测，所有人物、机构和资料均为测试样本。文中的完成数指程序接受并保存结果，不表示分析质量通过。

上一轮，据理三道题都没能交付正式结果。有的读错了资料编号，有的多写了不允许的字段，还有一道已经问到了用户的补充信息，却在最后把用户陈述装进了错误的结果类别。

这轮我先回头检查：模型看到的要求，和代码真正执行的要求，是不是一致？

检查后发现，有一条约定确实没有表达完整。代码要求“文档事实必须带有非空引用”，但提供给模型的结构说明，没有把这个条件完整写出来。模型写出的内容可能符合它看到的结构，却被运行时拒绝。

于是，这轮把这条条件补进了模型可见的格式要求，同时说明几种信息应该怎样表达：原文中记录的内容可以引用文件；用户在对话里补充的话，要说明来自用户，并作为条件推断或未核实限制来使用，不能伪装成原文已经证明的事实。

另外，也把“文件版本编号”和“证据编号”分清楚：先搜索，等搜索返回可用的证据编号，再读取对应原文。不能把目录里的文件编号猜成证据编号，也不能在还没收到搜索结果的时候，假装已经知道该读哪一段。

原有的字段、引用、权限和预算校验继续保留。本轮使用普通流程，上一轮新增的审查模式仍然默认关闭，没有继续往流程里叠加阶段。

然后，我跑了两道真实模型测试。

**两道题都保存了正式结果。但其中一道，仍然没有完成它应该做的关键追问。**

第一道是资料里缺少出勤安排的岗位匹配题。这次模型先检索，再回读了两份原文，最后交回一份能够通过校验的分析。

它也准确看到了问题：岗位要求每周现场工作三天，申请人的资料却没有说明能否满足这一点。这项信息会直接影响是否值得投递。

但它依旧没有停下来问。

它把问题写进了结果里的问题列表，又在建议中说“先确认现场办公可达性”，随后就结束了任务。运行器没有进入等待回答的状态，我也没有机会提交事先准备的回答卡。

对程序来说，这是一份结构合法、引用经过回读、可以保存的结果。对这道题的实际要求来说，“提出问题—收到回答—更新判断”还没有发生。

所以，这道题的关键交互要求仍然不通过。不能因为状态写着 completed，就把漏掉的交互算作完成。

第二道是两份方案相互冲突的研判题。

这次，模型分别搜索了三份资料，拿到证据编号后，再回读三份原文。随后它真正停下来问：两份同日记录没有明确优先级，现在准备采用哪一份，依据是什么？

等问题出现后，我才按冻结回答卡提供相应事实：拟采用甲记录的两人配置和116000元报价；乙记录是未完成确认的调整稿；正式确认材料还没有补上。

收到回答后，模型继续生成了分析。它把这段补充明确标成“用户自报”，使用条件推断类别，没有伪造文件引用。这次也保留了原文中的验收日期2025-06-20，没有重现更早一轮错写年份的问题。

这条交互走通了，正文仍然有瑕疵。

一处把“五项必要条件”写成了“四项/五项”。摘要说“自报条件下可参与”，正文限制段又说“不能据此认定满足条件”。条件判断和正式证明之间确实需要区分，但这样的表达容易让读者弄不清：现在究竟能给出什么程度的结论？

这些问题不一定触发格式校验，却会影响答案是否清楚、前后是否一致。结果能被保存之后，仍然需要逐段看内容。

原计划里的另一道资料充分题，这轮没有启动。

两题一共用了7次模型调用，累计用到35/36次，还剩1次。费用额度也仍有剩余。不过，仅剩一次调用不足以合理安排下一题的检索、回读和分析，所以我停在这里，把第三题明确记成“未测”。没有把它算作失败，也没有把剩余次数写成已经耗尽。

工程验证本身也留下了一次失败。

第一轮完整离线测试是560项通过、3项失败。新增说明让请求变长，三项已有流程测试超出了原来的输入预算。我压缩了重复说明，保持默认预算不变，再跑完整测试，563项全部通过。

这些测试说明格式约定、权限、预算和状态流转等机制经过了检查。它们不能保证模型总会追问，也不能保证答案里的每一句话都一致。

本轮的记录因此分成几层：格式和引用层面，两道已执行题都得到正式结果；关键交互层面，缺出勤信息题仍然漏问；内容层面，方案冲突题仍有表述与一致性问题；资料充分题则没有运行。没有哪一个单独的“通过数”，能替代这些具体情况。

两道题各只跑了一个新试次，而且本轮使用普通模式，上一轮使用实验审查模式，不能把差异简单归因于某一句提示改得更好。原始响应、失败记录和冻结题目都保留着，后续还需要继续对照。

本轮费用上界为0.088394元。累计费用上界加历史未知预留占用0.590738元，5元授权还剩4.409262元。这是保守的预算记录，不是供应商实际账单。

我现在更清楚地看到：把输出格式写对，是让据理能够工作的一个条件。它还需要知道什么时候该继续分析，什么时候该等用户回答，以及怎样把已有依据、用户陈述和判断限制讲清楚。

下一轮要继续面对的，就是那句已经出现很多次、却仍没有真正变成动作的“建议先确认”。
