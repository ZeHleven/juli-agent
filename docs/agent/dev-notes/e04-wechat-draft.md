# 让 Agent 真正停下来问一句，比我想的复杂

本地草稿，未经发布。素材来自据理的三组合成评测，不含真实求职者或企业资料。

上一轮测试据理，三道题都读到了原文，最后却一道也没完成。

有个共同的问题：我让模型把场景分析结果写成一段 JSON 字符串，再把它塞进外层 JSON。模型交回来的东西能解析，但装错了内容——本该写分析摘要的地方，变成了输入资料目录。

还有个更影响使用的问题。模型已经发现信息缺失或者材料冲突，却只是写下“建议进一步确认”，没有真的停下来问我。

我想要的问答分析，显然不能止步于这句话。

这轮先改了输出约定。模型可以直接交一个原生的结果对象，由代码负责转换成系统原来保存的格式。分析和追问也分成两个明确的出口：能继续分析就交结果；关键未知会改变判断，就只提出一个聚焦的问题，等待回答。

原来的校验继续保留。引用有没有回读过、资料是不是这项任务允许使用的、结果是否符合场景要求，仍然要逐项检查。不能为了让测试变绿，就把校验删了。

完成修改后，409项离线测试通过。随后，我重新跑了相同的三道合成题，用真实模型调用看看表现。

这次，三题中有两题完成了流程，一题失败。

第一题是背景资料充分的岗位匹配。模型检索并回读了两份原文，提交了符合格式的分析。上轮它把已经明确接受的每周三天现场出勤，又写成了“资料未记录”；这次主要分析承认了这项已知信息。辅助复核仍发现一个可改进的地方：后续问题列表里，又宽泛地问了现场安排是否有限制。它没有因此暂停，但回答还可以更干净一点。

第三题是两份方案冲突：一份写两个人、报价116000元，另一份写一个人、报价128000元，两份记录又没有明确的替代关系。

这次，据理读完三份材料后，真的停下来问了：准备采用哪一份方案，依据是什么？

等它问完，我才按照事先冻结的回答卡，补充对应事实：拟采用两人和116000元的方案，另一份是尚未完成确认的调整稿，正式确认材料还没有提供。我没有把整份评分卡发给模型，也没有告诉它应该得出什么结论。

收到回答后，它继续完成分析，区分了“用户表示拟采用”和“原始文件已经证明”。方案意向得到澄清，正式依据仍待补齐。这一题，才真正走过了“发现冲突—追问—收到回答—更新判断”的过程。

第二题却暴露了另一个问题。这道岗位匹配题没有提供申请人能否接受固定现场出勤的信息。模型只搜索了资料，没有调用原文回读，就直接给出了分析，也没有真正追问。

虽然这两份短文的搜索片段碰巧包含了全文，框架仍然没有把它当作完成回读。最终结果因 `evidence_not_read` 被拒收，没有保存成成功答案。

它在文字里知道“这件事还不清楚”，并不意味着它就会按流程去确认。搜索能看到一些文字，也不意味着它已经完成了引用所要求的取证步骤。这一题需要继续改。

所以，我把本轮记录为：流程完成从0/3变成2/3，真实追问并收到回答后继续分析的案例有一个。不能据此说据理已经可靠，更不能把这三个样本换算成对外宣传的准确率。

两道完成题的关键内容，在独立 Agent 的辅助复核中满足了本次要求，但还没有经过人工终审。缺失信息题的回答后表现仍然没有测到；更长的文档、PDF/OCR、其他场景和重复运行的稳定性，也还没验证。

本轮9次调用的费用上界按保守价格计为0.106178元。连同前轮已计入的费用上界和最早一次仍保留的预留，累计占用0.387238元，仍在最初的5元上限内。这是评测预算记录，不是服务平台账单。

做这轮之前，我最想解决的是“让模型把结果写对”。做完之后，更明确了下一步：让它在该读原文的时候读原文，在需要回答的时候真正停下来。两道完成的题留下，一道失败的题也留下，下一轮继续对照着看。
