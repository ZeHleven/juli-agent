# 持久 Agent 运行器（M05）

运行器提供受信 Python 装配入口及离线演示。M06 已接入 [执行 API 和本地工作台](workbench.md)，默认禁用模型；没有后台工作进程和 HTTP 事件推送。没有调用真实模型，结构和引用检查不代表分析质量通过验收。

```bash
python -m juli runtime-demo --directory scenarios
```

此命令在临时合成库中完成追问、回答、检索、回读和保存结果，每个动作间重新创建存储和运行器对象。输出 `real_model_calls: 0`、`network_calls: 0` 和 `task_status: completed`。这里的 completed 是脚本任务流程完成。

## 装配与继续

先显式迁移据理独立数据库，再使用已认证主体创建空间、资料、会话及任务。不要接入原应用数据库。

```python
from juli.bootstrap import create_durable_runner
from juli.application.model_session import SessionPolicy

runner = create_durable_runner(
    store, token, workspace_id, task_id, provider,
    profile="deployment-model-profile-v1",  # 部署者定义，不由用户上传文件指定
    policy=SessionPolicy(),                # 默认禁止外部模型外发
)
outcome = runner.run()                     # 直到 completed / pending / failed / cancelled
if outcome["state"]["status"] == "pending":
    runner.answer(
        expected_version=outcome["state"]["version"],
        request_key="stable-answer-request-id",
        text="用户对本次追问的回答",
    )
    outcome = runner.run()
```

`step()` 只执行一个模型或工具动作；`view(after=cursor, limit=100)` 返回当前状态、预算、结果和分页事件，`next_cursor` 用于增量读取。事件仅含序号、类型和时间，不含提示词、资料或密钥。`cancel(expected_version=...)` 与已有取消 API 使用同一数据库任务状态。

重启后，用同一任务 ID、原主体的有效令牌、同一部署配置重建运行器。模型端点、型号、窗口和超时在 HTTP 适配器中参与配置指纹，密钥不参与，允许同一配置轮换密钥。自定义 provider 如有影响模型行为的配置，应提供稳定、非敏感的 `runtime_identity`；部署 profile 必须随配置改变，不能拿任意名称伪装相同配置。政策、提供者类型、外发属性与上下文窗口也固定在任务上。

框架不保存令牌或模型密钥，也不会从旧项目或环境中自动寻找密钥。外部模型仍须显式配置已批准端点，并将外发政策设为允许；本轮没有进行这种实际调用。

## 执行与中断语义

1. SQLite 写事务先检查当前身份、资料快照、场景和预算，预留唯一动作及输入/输出/时间额度。
2. 事务外调用模型或工具，不持有数据库写锁等待响应。
3. 新事务核对动作票据、期限、当前授权、任务状态和有效资料，再保存消息、引用校验后的结果与状态。完成状态和结果一起提交。
4. 取消会使动作票据失效；随后返回的结果不能提交。取消不能追回已发给外部模型的数据，也不能强制停止任意第三方 Python provider。

同一会话只允许一个活动任务，等待追问时也保留占用；完成、失败或取消后释放。只有任务创建者可以执行、回答和读取运行详情，其他空间编辑者不能接管其回读凭证。原有空间写权限仍可取消任务。

已提交的模型工具请求可在重启后继续执行工具。**如果进程在预留动作后中断，系统无法证明调用是否发生或完成；动作到期后的下一次 `step/run` 会将其记为 `unknown`，任务失败，保留预算，不自动重放。** 尚未到期时返回 `runtime_busy`。没有后台自动扫描器，需由调用方再次推进或取消。要重新尝试，明确创建新任务，不在旧任务里重置预算。

提供者抛错、超时、响应无效或提交失败也采用保守停止策略，原始错误正文不会入库。该策略不宣称恰好执行一次；尤其不能推断外部服务是否已经收费。成功工具读取可能已经留下回读凭证，但没有有效动作票据就不能完成任务。

## 预算和数据

- 动作数、模型次数、消息、待执行工具、用过的调用 ID、输入及输出预算都持久保存。重新实例化不会重置；已纳入持久运行的任务不能再通过旧 `ModelSession` 绕过预算。
- 输入额度沿用 M04 的保守字节估算，结合模型报告的 usage 向上计费，不是供应商精确 tokenizer 或账单统计。已知合法响应可释放未用完的输出预留；未知结果保留全部预留。
- 时间额度计算累计活动执行时间，等待用户答复不消耗它。每个动作最多预留 30 秒，完成后释放未用部分；未知结果保留时间预留。SQLite 期限使用同机系统时钟，部署者应维持系统时钟稳定。
- 对同一追问重发相同请求键、版本和回答不重复追加消息；同键更改内容拒绝。状态版本不同的回答拒绝。
- 检查引用来源和回读凭证与完成提交处于同一事务。读取已完成结果时再次核验引用来源；来源撤下后不返回旧引用结果。
- 消息和回读内容会进入 SQLite checkpoint，数据库仍为本地明文资料，需保护文件权限。撤下不是物理删除；删除与保留策略尚未实现。
