# 本地部署与运行维护

首版部署范围是单机、回环地址、SQLite。启动命令和界面操作见 [安装指南](getting-started.md)。先使用明确标记的离线演示理解流程，再按具体场景验收真实模型。

## 配置与运行目录

源码、虚拟环境和运行资料应分开管理；示例将虚拟环境放 `.venv`，据理数据库放 `.local`，二者均不进入发布包。`--directory` 明确指定部署者安装的场景目录，`--database` 明确指定据理数据库。

身份由本机管理员创建，空间成员由所有者管理。管理员负责保管数据库及访问令牌；SQLite 内保存令牌摘要，资料正文和原件仍为明文。工作台刷新后需要重新输入令牌，页面不会持久保存它。

## 更新和迁移

1. 停止服务，并确认没有该数据库的活动写入进程。
2. 使用受保护的备份方式保留当前数据库，以及对应的代码版本和场景包。备份也是敏感资料，不能进入 Git 或公开附件。
3. 在副本上用目标版本的 `db check` 检查；若版本需要升级，显式执行 `db migrate` 并验证资料和任务，再更新实际运行实例。
4. 不把旧版程序直接连接到新版数据库；本项目没有迁移降级工具。回退应使用匹配的旧代码与升级前备份，并先在隔离副本上验证。

本文是操作顺序说明，不代表已经为用户数据库执行备份、迁移或恢复演练。当前程序没有自动备份、自动升级或恢复调度。

## 模型和费用

默认没有真实模型执行。模型目标、密钥、外发许可和任务预算由受信服务端配置；禁止客户端控制这些值。外部模型可能收到问题、资料目录及被检索/回读的片段，请根据实际资料和供应商明确授权范围。

任务预算不是计费上限保证。输入计量采用保守字节估计，实际模型用量另有校验；供应商对失败或未知调用的收费不能靠本地回滚撤销。未知结果停止，不自动重复付费调用。详见 [模型](models.md)、[运行器](runtime.md) 和 [预算配置](workbench.md)。

## 暴露范围

当前 CLI 固定监听 `127.0.0.1`。网页、身份方式、限流、存储配额、解析隔离和运营流程尚未按公网服务验收；没有本项目维护的公网 Docker Compose、TLS 网关或托管 SaaS 部署方案。

若要扩展到团队或公网使用，应先明确身份与访问边界，并实现和验收相应部署能力。不能仅把监听地址改成 `0.0.0.0` 就称作生产部署完成。场景说明、合成验收和提示词隔离均不能替代运行环境的保护。
