## 开始前的计划

准备岗位匹配、招投标研判、课程选择三个场景，每个场景四种资料状态：充分、关键缺失、冲突、长文中的关键条件。使用虚构人物、机构和规则；评判仅依据提供的材料，不借用真实招聘、采购法规或课程制度。

新增四个成对变体，用于检查关键事实改变是否影响结论，以及无关措辞或资料顺序是否改变核心判断。岗位和招投标用于开发，课程选择预留后续验证。预留集由开发者编写并可见，不能宣称为独立盲测；如果以后用其结果调整提示词或实现，须转为开发集并另补新题。

资料正文与评审答案分别放置，未来运行仅按题目清单上传指定正文；不得把评分标准、文件名中的状态提示或正确答案发送给被测模型。允许结论范围而非固定措辞，每个关键事实给出可定位的原文和人工核对标准。追问样本同时提供给测试操作者的回答卡，并区分用户陈述与文件事实。

## 验收条件

- 12 道基础题覆盖 3×4 组合，4 道附加变体有明确基题与变化义务。
- 资料均为新造合成文本，不含真实个人/企业资料、凭据或旧数据库。
- 每条带证据的评分事实可以匹配原文，记录文档、行号、字符范围和文件 SHA-256。
- 长文样本超过单个片段长度，关键条件出现在后半部；不把这种文本测试称作 PDF/DOCX 或 OCR 验收。
- 场景角色、缺失条件与结果 schema 能被现有公共接口表达；新增课程场景只在评测目录，不改变核心或默认场景安装。
- 自动检查只验证样本结构、来源和包兼容性；人工审阅答案是否充分、冲突是否合理。所有模型结果、分数和费用保持“未运行”，不填假零分或通过率。
- 留存基线、检查结果、修订原因和未覆盖项；只做本地交付，不提交、推送或发布测试集。

## 结果

交付位于 [案例目录](../../examples/quality_eval/v1/README.md)，可从 [案例导航](../../examples/quality_eval/v1/CASEBOOK.md) 逐题浏览。12 道基础题加 4 道配对变体，共 35 份输入文档、85 条评分项和 179 处原文引用。每个场景均覆盖充分、缺失、冲突、长文；岗位与招投标额外覆盖关键条件变化、无关内容变化。新增课程场景位于评测目录，未装入默认场景目录。

评分标准按每项 0/1/2 分人工判断，尚未审阅的结果保持空值；关键项不由平均分抵消。评分同时观察证据、结论、未知项、追问与回答后更新，并区分初始判断和收到回答后的阶段。来源索引含逐字引用、文件 SHA-256、行号和字符位置；它证明来源可定位，不自动证明模型结论受证据支持。

### 复核中的修改与失败尝试

- 岗位与课程长文初稿未达到长度门槛，补充自然业务/学习安排段落后重查。最终三个长文按 UTF-8 解码后的字符数分别为 5626、6761、4782，决定性条件放在后半部。这是测试资料编写问题，没有对应模型错误。
- 独立审阅发现课程目标“8周内”未说明起算点；四份背景与评分引文同步改为“从课程开课日起8周内”，避免合理的日期解释被误判。
- 招投标缺失题的输入原本直接提示如何对待口头陈述和未知项，影响观察能力；移除这些提示，只保留参与项目所需的正式凭证规则，证据分级要求留在评审标准。
- 缺失及冲突题区分回答前、回答后标准，避免补充信息已解决问题后，评审仍错误要求保持“不确定”。用户回答仍标为自述，不能伪装成原文件证据。
- 沙箱内 Python 子进程读取 Git 基线遇到所有权限制，没有修改全局信任配置；改用已保存的 124 文件 SHA-256 清单核对基线与交付。Windows 搜索通配符写法也做了调整；这些均为本地检查环境问题。
