# E02 运行与记录

这个入口只运行 E01 中的三题：`career-01`、`career-02`、`tender-03`。使用 DeepSeek 官方接口、用户选定的 `deepseek-v4-flash` 请求名称、非思考模式；旧模型名当前由 V4.1-Flash 服务。它是评测适配层，没有更改正式运行器或冻结测试资料。

在仓库根目录和已安装开发依赖的环境中，先执行无网络预检查：

```powershell
python -B -m examples.quality_eval.smoke --case career-01
```

没有 `--live` 时不读密钥、不创建运行数据库、不发模型请求。真实运行必须已经取得数据外发和费用授权，并显式提供本地密钥文件：

```powershell
python -B -m examples.quality_eval.smoke --live --case career-01 --api-key-file .local/e02-deepseek-api-key.txt
```

另外两题分别修改 `--case`。三题共享 `.local/quality-eval/v1/e02-deepseek-flash-20261002/budget/` 中的持久费用账本；每题只能新建一次，已有运行目录时拒绝覆盖。不要删除目录来绕过未知调用状态或预算。需要新一轮时先核对原调用、保留费用和原始记录，再明确建立新轮次。

程序使用同一进程等待追问回答，最多等待十分钟，不保存测试主体的访问令牌。出现 `clarification_pending` 后，操作者先读实际问题，只提供与之有关的原回答卡内容；不要整份上传评分卡。按输出路径创建 `answer-001.json`，内容为：

```json
{"text":"仅填写对本次实际追问的回答"}
```

保存后程序会记录答案并继续同一任务。最多处理三轮追问。未收到回答时保留 pending；超时或进程退出不重建任务续费重跑。首轮没有实现命令行跨进程恢复；核心 DurableRunner 的恢复能力不等于本入口已实现恢复管理。

每题目录保留：实际输入文件、任务及源码指纹、每步状态、工具提案与返回、追问和答案、最终 outcome。旁边的模型轨迹目录保存请求正文和 HTTP 200 返回（限长），不保存密钥、Authorization 或错误响应正文。模型协议失败也保留已经收到的可见返回，以区别协议不兼容与推理错误。

预算按 [官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 的高峰未命中缓存费率估算，不是账单查询。每次先按整个 64K 输入窗口和最多 4096 输出预留；三题合计最多 36 次，本轮用户最终批准总上限为 **5 元**。若下一次保守预留超过剩余预算，提前停止，不能为了凑足三题或 36 次调用而增加额度。未知调用保留预留并停止，程序不自动重试。输入单位不是供应商 tokenizer；服务端账单与用量异常需单独核对，不能宣称程序能撤回已发生收费。

结果需要对照 [E01 人工标准](../../examples/quality_eval/v1/rubric.md) 审阅完整轨迹。`completed` 仅表示合同与任务流程完成；评分、事实支撑和判断质量不能从这个状态推导。
