## 发现方式、样本与差异

E02 使用冻结的 career-01 合成资料调用 DeepSeek，收到 HTTP 200；原响应包含两个 evidence.search 工具调用及说明文字。原模型合同仅容纳单工具且禁止说明文字，因此拒绝响应。未执行任何工具，无法评价研判质量。原始返回、源码哈希、四种离线回放及费用账本保留于 E02 目录，参见 [E02 结果](round-02-result.md)。

预期：完整保留供应商的一条消息和所有工具提案，允许说明文字；工具逐项经过原网关、权限、参数和预算验证，串行执行。不能丢掉第二个调用、伪造第二次模型回答，或把说明文字当作最终分析。

## 改动计划

1. 为模型回复与历史消息增加有界工具列表，兼容既有单工具字段；保留说明文字、调用 ID 和顺序，拒绝重复 ID、超长列表、未授权或非法调用。
2. 持久 checkpoint 保存当前工具及剩余队列。一次模型调用只计费一次，每个工具独立占用动作、单独预留与提交；整批提前校验，执行时仍重查授权和资料。队列处理完才允许再次询问模型。
3. 旧单工具 checkpoint 可读；新配置有明确协议指纹，避免旧任务无声切换语义。既有数据库迁移 DDL 不变。旧内存测试会话不具备批次持久能力，明确拒绝多工具，避免静默丢弃。
4. E03 新建明确试次，保留 E02 失败任务和 unknown 账本。旧预留 ¥0.160768 全额计入累计预算，E03 可用上限最多 ¥4.839232；不把估算 ¥0.003688 当作已对账金额释放预留。

## 验收条件

- 原始双工具加文字响应在离线回放中完整解析；再次请求含一条完整 assistant 消息和两条有正确 ID 的 tool 结果。

- 中间失败、取消、撤权、资料撤下后，余项停止；未知调用不重试，模型和动作预算不重置。

## 具体修改与失败尝试

- 模型合同保留单工具字段并增加最多8个的工具列表；HTTP适配完整解析与回传批次、说明、原调用ID和顺序，整批拒绝非法项目。
- checkpoint增加有界待执行队列，旧JSON缺省为空；持久运行器将单个模型回复计一次调用、每个工具计一个动作，执行前后仍由原事务和网关校验权限、资料和版本。
- 运行配置加入消息协议指纹。旧任务不会悄然使用新语义继续，数据库迁移DDL不变。旧内存ModelSession仍为单工具连接测试入口，收到多工具明确拒绝。
- 首次回归为65通过、1失败：新批次预算预检改变了旧单工具预算不足时的返回方式。修正为多工具整批预检，单工具保留原下一动作准入机制；两项定向测试随后通过，再跑完整回归。
- 独立复核发现共享提示词允许批次、旧内存会话却拒绝批次的不一致。现在按受信运行器能力生成说明：旧入口只许一个，持久运行器允许最多八个。
- 继续入口为用户明确授权的新试次建立继承声明和共享子账本。每次操作复核旧账本及子账本指纹；在已有 E03 目录内删除或替换账本会停止执行，不能因此清零费用。来源使用稳定逻辑标识，记录复制到独立仓库后仍可验证。当前没有目录外的初始化凭证，无法识别整个 E03 目录被删除后重新初始化的情形；必须保留整个批次目录，不应把它视为能抵抗本机持有者删改的计费系统。
- 新源码版本为0.1.0.dev8。本轮未构建或发布wheel，未部署生产服务。
