1. 保存E05交付的228份源码文档到本地e06-baseline，并核对独立仓库与工作副本哈希相同（已完成）。
2. 明确四种现有声明类型的使用方法：文档事实需要真正读过的文档引用；用户补充信息作为注明来源的条件推断或未核实限制表达，不伪造文件引用。把fact需要非空引用及引用唯一性同步表达在模型可见JSON Schema，继续严格拒绝非法原响应。
3. 给出明确分析输出外壳与禁止输入元数据进入输出的规则；保留额外字段拒收。不删除模型返回字段，不自动修复原始响应。

6. 新建E06只读继承E02–E05完整预算、标记、已开始案例和哈希链，先预留后请求、未知停止。按career-02、tender-03、career-01顺序各最多一个新试次；剩余调用不足以合理完成下一题时不启动，明确记录未测。8次调用不是保证能完成三题。

## 验收条件与风险

- 新合成离线样本验证：空fact引用、重复引用、输入额外字段仍拒绝；合法用户条件推断可保存且不产生伪造读取凭证；输出Schema与Python结果合同对这些边界一致。
- 工具顺序与不同标识的提示和描述一致；实际取证、越权/撤销/取消、预算、持久重启原有测试通过。若仅改提示，不能把脚本模型遵从当成真实效果证明。
- 冻结题目、文档、场景包、金标、回答卡和旧记录均不改；原响应只做脱离网络的验证，不把修改过的回复记成新实测。
- 真实试次保留全部输入输出、工具、追问和回答，区分正式完成与辅助内容评分；只有实际pending后才提交既有回答卡。预算不足、校验失败、未知均如实停下，不补跑。
- 更明确的提示未必保证模型遵从；普通模式仍可能只搜索不回读、重复质疑已知信息或漏掉关键冲突，需分别记录。

`model_response.py`为模型可见ResultBlock补if/then非空事实引用和uniqueItems，并提供普通/审查模式共用的输出说明与证据工作流。`context.py`和`review.py`只在适用阶段加入，review阶段仍只有ready/clarify。`bootstrap.py`改工具及参数说明，未增加硬编码证据格式校验；错误版本ID仍由原存储严格拒绝，不替换、不重试。RESPONSE_PROTOCOL从v1提升为v2，拒绝旧配置静默续跑，保留现有公开结果合同、DDL和预算。
