# E05 实验：局部流程改善，三题最终交付失败

日期：2026-10-03（北京时间）。版本：`0.1.0.dev10`。**同三题新试次正式完成0/3，E04为2/3；本轮未达到效果验收要求，审查模式保持默认关闭。** 502项离线测试通过仅证明已测机械流程，不冲抵真实失败。

三题输入、场景和评分标准不变，判断基准日仍为冻结的2026-10-02；不是把运行当天替换进题目。没有重试、修改错误响应、补造引用或删除失败。本轮只在本地开发和验证，没有推送、发布或部署。

## 设计与实际边界

新增服务端显式启用的`review_before_final=True`：先收结构合法的草稿，框架按照草稿选择的至多8个证据片段实际回读，再单独审查是否有会改变判断的关键未知；需要时进入pending，收到回答后再审查，ready后才生成最终结果。原权限、读取凭证、预算和最终校验保留，普通模式保持E04路径。

这是已收到草稿之后的计划内步骤，不是遇错自动重试。框架安排的工具消息明确标记Framework-scheduled，不能写成模型自发回读。阶段保存在同一任务检查点；所有模型/工具步骤照常预留预算，异常或未知立即停止。具体实现、测试失败和修正见 [本轮计划](round-05-plan.md)。

这个设计只能确保已选证据经过读取、已声明关键未知进入交互，不能证明模型选全了资料或找全了未知。新增的阶段和输出种类增加了遵从负担，本次结果不能支持默认推广。

## 三题实际结果

先测上轮失败的career-02，再测另外两题；执行期间代码、提示词和配置没有修改。

| 案例 / 总试次 | 模型调用 | 模型安排的工具 | 框架安排的工具 | 正式结果 |
|---|---:|---|---|---|
| career-02 / 3 | 5 | 2次search | 2次read成功 | 真实追问、回答、再审查已完成，最终analysis声明类型非法 |
| career-01 / 4 | 3 | 2次search、2次read成功 | 无 | 拟稿多出根级trust字段，在草稿入口拒收 |
| tender-03 / 3 | 1 | 3次search成功、1次read失败 | 无 | 把资源版本ID当证据ID，not_found，尚未生成分析 |

总计9次模型调用，12次工具动作尝试，其中11次成功、1次失败。三题状态均failed、result均null。只有career-02实际接受草稿并进入新增审查阶段；不能把其他两题被拒收的文本包装成“审查后的最终答案”。

### career-02：该问的问题终于问了，最后仍交不出结果

模型在两个搜索后提交合法草稿；框架随后真实回读两份短文，全文覆盖2/2。它不是模型自行补发的read，不能据此说模型主动取证已修好。

审查返回clarify，系统真实pending，询问是否接受每周现场三天，还捎带问了城市和最早入职时间。此时才按冻结回答卡提交：

> 我可以每周到现场工作三天，能够按岗位安排出勤，不需要全远程。

没有补造城市或入职时间。下一次审查返回ready，明确已采纳现场出勤答复，将作品和经历证明归为核验建议，没有重复pending。说明额外问城市/入职时间并非本题最小必要追问，应继续压缩。

最后一次analysis第3块正确说明出勤来自本轮用户答复、不是原文件，却使用`kind=fact`和空`evidence_ids`。现有事实块合同要求文档引用，因此触发`invalid_model_reply`，正式result仍为空。这不是虚构了一句用户答复，也不是应当随便加一个文件引用；要解决的是用户陈述的来源表达与严格合同的对应。当前JSON Schema未完整表达这一Python跨字段校验，下一轮需一并核对模型可见约定。

独立辅助评审对完整交互的experience、technical_work、collaboration、onsite_unknown、ask_and_condition均评2，回答后采纳也满足文字层面要求。但这只诊断被拒收内容，**不能记成正式通过**。最终第7块“已验证不影响匹配方向”措辞偏强，不代表外部核验。

### career-01：拟稿混入输入标记，已知信息又被质疑

模型自发搜索并完整回读2/2原文后，拟稿根对象包含多余`trust:"untrusted_user_data"`。严格分析结构不接受该字段，草稿尚未进入框架回读、审查或最终阶段就停止。

辅助检查拟稿第4、5块和摘要先承认可接受三天现场，第11块又称是否真的愿意现场仍须确认，与背景已说明的意愿冲突。这次不只是可选的通勤约束建议，onsite关键项记0；experience、technical_work、collaboration及非关键limits各2。没有实际pending，不应说已发生重复追问；审查是否能纠正这个拟稿问题也未测到。

这项内容问题在E04没有重现，E05又出现。不能因为新增了一个审查阶段，就先假定它一定会修好草稿；本次根本没运行到那里。

### tender-03：还没看到搜索返回，就用错标识读取

唯一模型回复同批生成三个search和一个read。第四项把绑定资料目录中的`version:...`传给read的`evidence_id`，而该工具需要搜索返回的`evidence:...`。三个搜索已返回正确候选，但模型生成整批请求时还没有机会看到这些返回，因此是标识种类与调用依赖错误；不是资料不存在、检索漏文或解析丢失。

工具拒绝错误ID并停止，没有自动猜测替换。没有草稿、成功回读、审查、追问或最终结论；六个内容评分项均**未评**，不能用六个0分冒充内容能力评测。
