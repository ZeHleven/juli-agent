# E07：声明关键问题后，真正等待回答

日期：2026-10-09。问题：JULI-003。范围：普通持久运行器的离线结构修复；真实模型效果待测。

## 怎么发现

E06 career-02 的第三次真实模型回复已经指出现场出勤会改变投递判断，却直接返回 analysis，把出勤和六个可选核验问题一起放入报告的 questions。任务 completed，无法提交原先冻结的回答卡。原始记录、评判与费用均保留；详见 [E06结果](round-06-result.md)。

本轮在修改前保存235份源码与文档，核对独立仓库与暂存目录一致，更新问题台账并写下 [E07计划](round-07-plan.md)。修复假设是：仅靠“遇到未知要追问”的文字提示不足，普通完成出口也应要求显式声明。

## 具体怎么修改

- 模型的普通 analysis 候选必须包含 `critical_question`。非空问题表示仍需用户回答，`null` 表示可以交付；空白、缺字段、混合或额外字段拒收，不猜测或自动补值。
- 有问题时，在同一提交事务中校验任务、场景、来源授权和原文回读，保存原始 assistant 消息及内部候选，进入既有 pending。公开 result 保持空，候选不作为最终报告展示。
- 用户回答沿用版本校验与幂等机制，作为 user 数据加入消息；随后按原预算继续。用户无法确认时允许模型给出带限制的条件分析，不机械要求重复追问。
- 原 `clarification` 出口保留。报告中的可选 questions 不自动升级为关键问题；不按问号、关键词或场景名称作判断。
- 响应协议升至 `native-analysis-v3`，旧v1/v2任务不可静默改用新语义。存储结果 AnalysisResult、四种 ClaimKind、数据库 DDL、默认预算不变。非交互连接兼容路径保留，普通持久入口不再接受缺声明的旧分析输出。
- E05审查实验仍默认关闭，没有新增必经审查调用、自动修复调用或付费重试。离线脚本显式构造新声明，不在真实响应接收处补 `null`。

## 前后效果

| 样本 | 修改前/观察 | 本轮结果 |
|---|---|---|
| E06岗位题原回复，字节不改 | 旧解析器接受，历史运行直接完成 | 新普通解析器拒绝缺少critical_question；未修改历史结论 |
| 新合成候选声明关键问题 | 用于验证新分支，无旧真实对照 | 实际pending，result为空，重启后保留原问题和原文 |
| 合成回答“可以”或“暂时不知道” | 脚本输出，不是模型能力证明 | 回答幂等、user角色保留；明确null后可完成条件分析 |
| 报告只剩可选问题 | 不应强制中断 | 明确null时可以完成 |
| 未回读、越权来源、场景/任务不符 | 不应借候选绕过 | 在pending提交前拒绝；撤权、撤资料和取消继续有效 |

旧回复被拒绝不等于真实模型已经学会追问。模型仍可能漏识别未知或错误声明null；用户是否真的能胜任、条件是否完整、概括是否准确也不由结构校验保证。JULI-003保持“结构修复完成、真实效果待验”，JULI-004/008的语义问题仍开放。

## 失败与修正

1. 首次定向测试57通过、1失败、99环境错误：沙箱临时目录创建失败，未把它当作模型或功能失败。第二次换到独立测试目录，模拟HTTP组运行停滞后手动中止，无完整XML，不计通过；随后同组在沙箱外以模拟HTTP执行。
2. 新增29项测试首次全部通过。模拟HTTP组13通过、1失败，定位为真实输入预算回归：同一合成四请求重建从31827升至32879，超过32000。
3. 压缩重复说明，移除与oneOf/const重复且不参与JSON Schema验证的OpenAPI discriminator mapping。保留校验条件及默认32000预算；重建总量降至31931，余量仅69，不宣称适合长对话。
4. 修正后重点回归186项通过；完整回归591项通过，耗时264.32秒，仅有既有的两项依赖弃用警告。源码分发检查240份文件通过；这不是完整安全审计。全部尝试保留在本地 `.local/e07-checks/`，中止的尝试单独记录。
